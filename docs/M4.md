# M4 — 数据模型补全：让角色技能落库真实发现

## 目标

把 `index.db` 的资产、漏洞、攻击链三张表从“指针最小集”扩成能承载真实发现的结构，
并让 `redteam_asset_add` / `redteam_asset_query` / `redteam_vuln_add` /
`redteam_vuln_query` / `redteam_chain_add` / `redteam_chain_list` 读写这些新字段。
只读面板同步展示新列。不触碰 `dispatch.py`、`__init__.py` 的注册矩阵和 Hermes core。

## 变更文件

- `store.py` — 建表 schema、`migrate_db()` / `_connect()`、`add_asset` /
  `query_assets` / `asset_test` / `vuln_add` / `vuln_query` / `chain_add` /
  `chain_list` 的字段扩展。
- `tools.py` — 对应工具 handler 与 JSON schema 的入参/过滤扩展。
- `dashboard/plugin_api.py` — `/summary` 与 engagement 元数据读取前先跑迁移。
- `desktop/plugin.js` — 资产页展示 地址/端口/服务/标题/状态；成果页漏洞条目展示
  标题/等级/资产/状态。
- `tests/test_chain_list.py` — 原测试用整字典断言 `chain_list` 输出，因返回新增
  `stage_code/tool/summary/created_at` 改为逐字段断言。
- `tests/test_m4_enrichment.py` — 新增迁移与字段读写测试。

## schema 变更

### asset

新增：`port INTEGER DEFAULT 0`、`service/product/version/url/title/names/provenance/
tool/scope/test_status/test_notes TEXT DEFAULT ''`。`stable_key` 从必填改为可选，
缺省时由 `address[:port]` 派生（port 为 0 时只用 address）。旧库保留
`UNIQUE(engagement_id, stable_key)`。

### vuln

新增：`title/severity/cve/target/evidence/confidence/gained/agent TEXT DEFAULT ''`、
`created_at TEXT DEFAULT CURRENT_TIMESTAMP`。原 `evidence_path` 不变。

### chain_step

新增：`stage_code/tool/summary TEXT DEFAULT ''`、`created_at TEXT DEFAULT CURRENT_TIMESTAMP`。

## 迁移

`migrate_db(db)` 用 `PRAGMA table_info(<table>)` 对比缺列，再逐列
`ALTER TABLE <table> ADD COLUMN ...`。`created_at` 在迁移中用常量默认值 `''` 加列
（SQLite 不允许 ALTER 加非恒定默认），随后把历史空值回填为 `CURRENT_TIMESTAMP`。
`_connect()` 打开任一 `index.db` 都先执行迁移，`open_engagement` 与所有读写路径共用
它；面板 `/summary` 也经 `_db()` 迁移。迁移幂等且对缺失表/全新库空操作。

## 行为变化

- `redteam_asset_add`：`stable_key` 不再必填；新增 12 个可选字段。更新已有资产时，
  只有显式传入的新字段才覆盖旧值，`address/status/last_seen` 保持原更新语义。
- `redteam_asset_query`：返回全部新列，新增可选 `status`（精确匹配）与
  `assessed`（`true` → `test_status <> ''`，`false` → `test_status = ''`）过滤。
- `redteam_asset_test`：沿用向 `status` 追加一段的行为（保证旧语义），同时把该段
  追加进 `test_notes` 并把 `test_status` 设为最新一段。
- `redteam_vuln_add` / `redteam_vuln_query`、`redteam_chain_add` /
  `redteam_chain_list` / `redteam_chain`：读写新增字段。
- 面板 资产 页与 成果 页读取新列。

## 风险 / 未竟事项

- 迁移采用 `ALTER TABLE` 加列；SQLite 不支持改列类型或删约束，旧库中 `stable_key`
  仍是 `NOT NULL`，由应用层保证派生键非空，无需重建表。
- `port` 与 `address` 的派生键未做规范化（例如 `http://host:80` 与
  `http://host:80/` 会得到不同键），如需去重应在调用侧统一地址格式。
- `asset_test` 同时更新 `status` 与 `test_notes/test_status`，`status` 会继续累积
  测试记录；若后续希望 `status` 只表达“生命状态”，需另行收敛。
- 面板改动仅更新了仓库内的 `desktop/plugin.js`，`~/.hermes/desktop-plugins/
  hermes-redteam/plugin.js` 的桌面半拷贝留到 M3 安装脚本同步。

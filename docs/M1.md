# M1 — 注册矩阵 / kwargs 会话 / 派单层

## 完成内容

1. 注册矩阵：`register(ctx)` 现在按 `ctx.profile_name` 分发。
   - `default`（指挥官）：只挂载读/命令面与派单工具，共 18 个，含
     `redteam_dispatch`、`redteam_dispatch_status`，不再提前 return，因此
     `hermes plugins doctor` 对 `default` 能看到非零工具。
   - `rt-recon / rt-asset / rt-vuln / rt-exploit / rt-internal`：各自按
     AGENTS.md 的角色工具集，外加共享读工具。
   - 每个 `rt-*` 只注册自己的 role skill；补上了 `rt-asset` 的
     `asset-correlation`。

2. 会话从 kwargs 读取：所有写工具 handler 改为
   `kwargs.get("session_id") or args.get("session_id")`，并把这些工具的 schema
   中 `session_id` 从 `required` 移除（写工具同时删除该属性，`redteam_session_bind`
   保留为可选属性）。`_root()` 也改为优先
   `hermes_constants.get_hermes_home()`，导入失败时回退
   `HERMES_HOME` → `~/.hermes`。

3. 派单层：新增 `dispatch.py`。
   - `redteam_dispatch`：校验 role ∈ {recon, asset, vuln, exploit, internal}，
     解析当前会话绑定或显式 `engagement_id`，检查
     `wiki/authorization.md` 缺失/空/仍为“待填写”即拒绝，随后执行
     `hermes kanban create <title> --assignee rt-<role> --workspace dir:<engagement_dir>
     --body <brief> --json`（30s 超时），返回 `{ok, task_id, assignee, status}`。
   - `redteam_dispatch_status`：执行 `hermes kanban show <task_id> --json`，
     返回 `{ok, task_id, status, summary, result}`。
   - brief 包含靶标、范围、边界、角色、靶标目录、任务与“用 redteam_* 工具记录”
     要求。

4. 测试：新增派单、kwargs 会话、注册矩阵测试；更新 3 个仍断言旧行为的既有测试。

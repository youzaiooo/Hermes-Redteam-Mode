# M5 — 跨靶标知识库 + 报告导出

## 目标

1. 在 `$HERMES_HOME/redteam/knowledge.db` 建立全局 POC 知识库：`poc` 表 +
   FTS5 全文索引，跨靶标去重与检索。

## 全局知识库 schema

`knowledge.db` 位于 engagements 根目录的上一层（即
`$HERMES_HOME/redteam/knowledge.db`）。只存元数据与清洗过的注记 / 证据路径，
不存 exploit 代码或凭据真值。

```text
poc(
  id INTEGER PRIMARY KEY,
  title, category, cve, target_pattern, source, source_url,
  verified INTEGER DEFAULT 0, verified_note, engagement, asset_target,
  created_at DEFAULT CURRENT_TIMESTAMP
)
poc_fts USING fts5(title, category, cve, target_pattern, source, source_url,
  verified, verified_note, engagement, asset_target, created_at)
```

FTS5 用独立表并显式以 `poc.id` 作为 `rowid` 写入，读取时先
`MATCH` 取 rowid 再回查 `poc` 拿真值，保证 `verified` 为布尔、字段始终最新。
`poc_update` / `poc_use` 更新 `poc` 后同步重建对应 FTS 行。

## 行为变化

### POC

- `redteam_poc_add`：必填 `id/category/asset_key/source_path`，新增可选
  `title/cve/target_pattern/source/source_url/verified/verified_note`。每次都写
  本靶标 `knowledge_ref` 指针与全局 `poc` 行；全局行按 `title + cve + source`
  去重，重复添加返回 `deduped: true` 与既有 id。`source` 缺省依次取
  `source_url`、`source_path`。
- `redteam_poc_search`：入参由 `category` 改为自由文本 `query`。先 FTS5 搜全局库
  （跨靶标），再按 `LIKE` 合并本靶标 `knowledge_ref` 与旧 `poc_ref` 指针，结果带
  `source` / `verified` 字段。查询串按空白拆词并加双引号转义，避免 FTS 语法错误。
- `redteam_poc_list` / `redteam_poc_get`：读全局 `poc` 表（按 engagement 过滤），
  返回 `id/title/category/cve/target_pattern/source/source_url/verified/
  verified_note/engagement/asset_target/created_at`。
- `redteam_poc_update`：写 `verified_note`，`status` 命中
  `verified/confirmed/reproduced/true/1/yes` 时置 `verified=1`。
- `redteam_poc_use`：记录一行结果到 `verified_note`，置 `verified=1`，返回
  `source` 与 `result`。

### 报告导出

`redteam_report_export` 从 `index.db` 生成四节：

1. `资产证明` — asset 的 地址/端口/标题/来源(provenance)/归属(scope，缺省用靶标名)。
2. `得分汇总` — `score_event` 按 `rule_id` 分组计数并列出证据路径。
3. `凭据与访问` — 只列掩码指针（`asset_key → evidence_path`），不出现任何口令/正文。
4. `漏洞复现` — vuln 的 标题/等级/CVE/证据 + 攻击链步骤的 工具/结果/摘要。

返回 `{ok, relative_path, excerpt}`；`excerpt` 为正文前 8 行截断到 300 字符。

### 面板与路由

- `GET /report/{id}` 优先返回 `reports/` 下最新的 `report-*.md`
  （`generated: false`），否则即时生成并返回（`generated: true`）；响应含
  `path/relative_path/filename/markdown/excerpt`。
- 报告页签按钮改为 `导出 Markdown`：先 `captureGatewayFileDownload()` 捕获下载动作，
  再 `ctx.rest` 读 `/report/{id}`，用返回的 `path` 与 `filename` 保存。

## 风险 / 未竟事项

- `knowledge.db` 为全新文件，无旧库迁移路径；若未来加列需单独迁移（沿用
  `migrate_db` 思路）。
- 去重后的全局行只记录首个 `engagement`；后续靶标再次引用同一 POC 时，
  `poc_list` 只在该原始靶标下可见，跨靶标检索靠 `poc_search`。
- `poc_search` 合并的本靶标 `knowledge_ref` 与全局行按
  `(engagement, asset_target)` 去重；跨靶标去重命中的 POC 会同时出现全局行与本靶标
  本地指针，属预期（保留本地引用）。
- 报告表格单元格只转义了 `|`；若字段含换行需在调用侧清洗。
- 面板改动仅更新仓库内 `desktop/plugin.js`，`~/.hermes/desktop-plugins/
  hermes-redteam/plugin.js` 的桌面半拷贝由 M3 安装脚本同步。
